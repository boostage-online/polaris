# Passation — Phase 7 (durcissement et pilote élargi)

Branche `feat/phase-7-hardening`, empilée sur `feat/phase-6-reporting` (PR #7 → PR #6 → … → PR #1). Backlog : `docs/backlog/phase-7-hardening.md` ; document directeur, section « Phase 7 » et Partie 11 (sécurité) ; ADR mises en œuvre : 0001 (RLS, exemptions), 0003 (worker), 0007 (permissions), 0008 (MFA, impersonation), 0009 (erreurs).

**Règle d'or de la phase** : rien de nouveau côté métier ; chaque ajout rend le système plus difficile à compromettre, plus facile à exploiter sans développeur, ou plus simple à remettre en route. Et toujours **sans nouvelle dépendance** npm (le lockfile est gelé en CI) : TOTP, codes de récupération, ZIP et CSP sont écrits à la main et testés.

## Décisions d'implémentation à connaître

- **MFA exigée par la nature de l'action, pas par le rôle** : le guard regarde les permissions qui ont ouvert la route ; si toutes sont sensibles, la session doit être MFA. Un rôle FINANCE sans MFA consulte tout mais n'encaisse pas tant qu'il n'est pas enrôlé — message explicite, lien vers Sécurité du compte. Le super admin est bloqué sur tout `/platform/*` sans MFA, mais pas sur `/me` (il faut bien pouvoir s'enrôler).
- **Défi MFA = JWT à usage unique** plutôt qu'une session « à moitié ouverte » : rien n'est écrit en base tant que le code n'est pas bon ; le `jti` est consommé dans Redis.
- **Anti-rejeu TOTP par compteur** : un code accepté ne l'est plus pendant 90 s (3 pas), ce qui couvre la fenêtre ±1. Les tests effacent ces marqueurs pour les comptes seedés (`solveMfa`) au lieu d'attendre la fenêtre suivante.
- **Impersonation = jeton court, pas de refresh** : la session de support ne se prolonge pas ; à 30 min, elle meurt. Le cache Redis `imp:<id>` (30 s) évite une lecture plateforme par requête tout en permettant la clôture quasi immédiate.
- **Alertes en table, pas en e-mails** : l'e-mail est une conséquence ; la vérité est la ligne (ouverte/résolue/acquittée). Le renvoi 6 h évite le bruit sans laisser une alerte s'oublier.
- **Anonymisation plutôt que suppression** : les contraintes comptables (10 ans) et l'intégrité référentielle (créances, reçus, feuilles d'appel) interdisent le `DELETE` ; les statistiques agrégées restent exactes.
- **Paramètres fusionnés par section** : `PATCH /tenants/:id/settings` ne remplace plus l'objet entier — un écran qui enregistre « notifications » n'efface plus « assiduité » (découvert par le test d'impersonation qui avait cassé les justifications).
- **CSP en Report-Only d'abord** : une CSP bloquante mal réglée casse l'appli pour tous les établissements d'un coup ; une semaine de rapports sur staging avant `CSP_ENFORCE=true`.
- **Audit des dépendances : critique bloque, haute avertit** : avec un lockfile gelé et sans accès au registre depuis l'environnement de développement, une vulnérabilité haute transitive sans correctif disponible bloquerait toute la CI ; elle est affichée dans le résumé de la PR et traitée à la main (Renovate à venir).
