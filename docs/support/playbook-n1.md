# Playbook support niveau 1

Pour la personne qui lit `support@polaris.app` et répond au téléphone. Aucune compétence technique n'est requise : tout se fait depuis **Plateforme → Support** (compte plateforme avec MFA) et par téléphone avec l'établissement. Ce que le niveau 1 ne peut pas résoudre en 15 minutes passe au niveau 2 (astreinte, `docs/runbooks/astreinte.md`) avec un ticket complet.

## Règles

1. **Identifier avant d'agir** : toute action sur un compte (déverrouiller, réinitialiser la MFA, session de support) suppose d'avoir vérifié qui parle — rappel au numéro connu de l'établissement, ou confirmation écrite du chef d'établissement. Pas d'exception pour « c'est urgent ».
2. **Le support voit qui et quel état, jamais quoi** : la recherche affiche comptes, rôles, verrouillage, MFA, invitations ; pas les présences, pas les paiements. Pour voir un écran de l'établissement : session de support, avec l'accord de l'administrateur (`docs/runbooks/impersonation.md`).
3. **Tout est journalisé** (recherches, déverrouillages, réinitialisations, sessions) et visible par l'établissement dans son journal d'audit.
4. **On ne modifie pas les données métier** d'un établissement (élèves, paiements, appels) : on guide la personne habilitée pour qu'elle le fasse elle-même.

## Les 10 demandes les plus fréquentes

Sinon : l'administrateur de l'établissement réinitialise (Personnel → Réinitialiser la MFA). Pour un **administrateur** lui-même : support, après identification renforcée (appel au chef d'établissement), **Réinitialiser la MFA**. |
| « Code à 6 chiffres refusé »                             | MFA activée, pas de verrouillage                                                                                                               | Heure du téléphone en automatique ; attendre le code suivant ; un code déjà utilisé est refusé.                                                                                                                                                                         |

Le support ne change pas les rôles.                                                                                                                                  |

## Le ticket niveau 2 (ce qu'il contient)

Établissement (code), personne concernée (e-mail ou téléphone, jamais le mot de passe), ce qui a été tenté, heure précise du problème, capture d'écran, et si disponible le **`trace_id`** affiché dans le message d'erreur. Sévérité selon `docs/runbooks/incident.md`.

## Mots à utiliser

- « session de support » (pas « je me connecte à votre place ») ;
- « réinitialiser la double authentification » (pas « supprimer la sécurité ») ;
- « en cours de vérification » pour un paiement, jamais « perdu » ni « échoué » tant que le provider n'a pas répondu.
